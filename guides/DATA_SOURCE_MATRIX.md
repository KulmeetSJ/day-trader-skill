# Day Trader: Central Data Capability Matrix

## 1. Overview
The market data infrastructure strictly segregates data by origin, latency, and truthfulness.
Under **NO circumstances** is simulated or estimated data described as actual exchange data, nor is Yahoo Finance represented as real-time tick data.

Every data payload carries authoritative metadata:
- `provider`: Provider identifier (`yahoo`, `upstox`, `offline`, `simulated`, `stooq`, `alpaca`)
- `source_timestamp`: Original bar or tick timestamp
- `retrieval_timestamp`: UTC ISO timestamp when data was received by the application
- `timezone`: Local market timezone (`IST` for India, `ET` for US)
- `data_age`: Age in seconds relative to current time or simulated replay time
- `data_status`: `CURRENT`, `DELAYED`, `HISTORICAL`, `FIXTURE`, `SIMULATED`, or `UNAVAILABLE`
- `tier`: `REAL_TIME`, `DELAYED`, `HISTORICAL`, `SIMULATED`, `FIXTURE`, or `UNAVAILABLE`
- `is_actual`: True only for real exchange data (current, delayed, or settled historical)
- `is_estimated`: True when derived via numerical modeling or price action estimation
- `is_simulated`: True when generated by synthetic fixture or Monte Carlo engine

## 3. Data Tier & Freshness Policy

1. **Yahoo Finance**:
   - `tier`: `DELAYED`
   - `data_status`: `DELAYED` or `HISTORICAL`
   - Never represented as guaranteed real-time exchange data.
   - Used for broad watchlists, historical daily/intraday bars, and free delayed monitoring.

2. **Upstox Provider**:
   - Read-only data integration (zero live order execution route).
   - `tier`: `REAL_TIME` when valid token provided and market open.
   - Respects actual subscription tier (Basic / Developer / Pro). Does not assume higher tier features than licensed.
   - When credentials expire or are absent, fails closed or gracefully degrades to explicit `DELAYED` Yahoo with logged warning.

3. **Offline & Simulated Providers**:
   - `tier`: `FIXTURE` or `SIMULATED`
   - `is_actual`: `False`
   - Used exclusively for offline unit testing, CI pipelines, and Monte Carlo historical replay.

## 4. Volume and Order-Flow Quality Distinction

Per Section 5 of the Master Directive:
- **Actual Aggressor Volume**: Only labeled as `ACTUAL` when incoming broker WebSocket or trade-level feed carries explicit trade tick aggressor direction flags.
- **Estimated Aggressor Volume**: When only standard OHLCV candles exist, volume pressure is labeled `ESTIMATED` with documented methodology (e.g. Close-relative-to-High/Low candle split).
- **UNAVAILABLE**: Stamped when depth or trade ticks are missing and estimation is disabled.
